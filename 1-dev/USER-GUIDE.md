# 📖 使用說明書 — Upwork 接案助手

> 站內同款頁面：登入後左側「⚙️ 進階 → 📖 說明書」(`/guide`)。
> 這份是給使用者的操作手冊，不是開發文檔(開發交接看 `AGENTS-PLAN.md`)。

**一句話**：每天打開 → 🤖AI 快篩 → 看 🟢EV 榜 → 對前幾名按🔎書籤校正勝率 → ②評估 → 💬助手寫提案 → 投 → 標結果。
**紀律**：少投早投投準、絕不亂 boost、衝第一個評價。

網址：http://upworkfilter.looptw.com　·　登入：auth.twloop.com 帳號

---

## 0. 這系統在幹嘛

瀏覽器擴充功能在你真實 Upwork session 抓案 → 餵進這站 → 四道門漏斗評分 + AI 重排 → 列出「最值得投」的案，並幫你寫提案、追蹤投標結果回頭校正。

**核心理念：能力分高 ≠ 接得到。** 前兩道門問「該不該做」，後兩道門問「0 評價新手搶不搶得到」。系統寧可少推、也不讓你燒 Connects 投不可能的案。

---

## 1. 一次性設定（裝一次）

1. **擴充功能**(Upwork-Job-Scraper)裝在 Chrome → 每 15 分自動抓案。**前提：Chrome 要開著**。
2. **書籤**：到 `🔎 即時分析`(`/analyze`) 把「🔎 Analyze this job」拖到書籤列。之後在任何 Upwork 案件頁點它 → 一鍵帶資料來分析 / 補真數據。
3. 鐵則：**AI 只在你打開網站時才跑**(省 token)。每天要真的打開它幾分鐘。

---

## 2. 每天標準動作（5 步，約 10–15 分鐘）

1. **AI 快篩**：`📋 探索案件` 頂部按「🤖 AI 快篩」，把新案評完分。
2. **看 🟢EV 榜**：預設 filter 🟢值得投、排序「🎯 最值得投」。最上面就是最該投的。看綠燈 + 🎯勝率% + 有沒有「🎯 第一單目標」。
3. **校正前 3–5 名 ⭐關鍵**：勝率有「**⚠️估**」= 缺客戶數據、樂觀估計。開那案 Upwork 頁 → 按🔎書籤 → 「存進列表」→ connects/聘用率變真值、勝率重算。
4. **進 ②評估案件**：看「勝率估計」區塊(接不接得到 + 為什麼 + 怎麼脫穎而出)。紅字「🔴別投 / 🚫別 boost」要當真。
5. **決定投 → ③寫提案**：建議點右下角 **💬 助手**，貼上 Upwork 投標頁完整內容(含 To Apply / 影片題 / 篩選題)說「幫我投這個案」。投完回卡片勾「已投」。

---

## 3. 投標之後（餵學習迴路）

到 `📊 投案追蹤`(`/applications`) 把結果標起來：**已回覆／面試／錄取／落選**。
系統統計「AI 預測勝率 vs 真實命中率」回頭校正未來估計。**你標得越勤，勝率越準。**

---

## 4. 評分怎麼運作（四道門）

### 🚪① 來源門
12 條精準搜尋查詢決定「什麼案進得來」；只收付款已驗證、依最新排序。

### 🎯② 能力門（該不該做）
命中以下 → 直接**硬擋**(不進 AI、規則分封頂 35)：
- **紅線核心**：no-code/平台工具(Make/n8n/Bubble/Streamlit/GAS…)出現在標題、描述前 400 字、或全文 ≥2 次
- **能力圈外**：完全沒命中你任何技能
- **非開發職**：招募/小編/客服/業務 掛 AI 羊頭

軟標(不擋但 APPLY 降 MAYBE)：你的強項是核心、只是順帶提到紅線 → 標 ⚠️ 自己判斷。

### 📊③ 評分門：7 維加權（現為新手模式權重）

| 維度 | 權重 | 衡量 |
|---|---|---|
| 🎯 能力匹配 | **25** | 會不會、交付得了嗎(+GitHub 作品證據) |
| 🥊 競爭強度 | **25** | 提案越少越高(<5=100、50+=0) |
| 🛡 風險訊號 | 15 | 未驗證/0%聘用/跳出平台/畫大餅 扣分 |
| 🏦 客戶品質 | 15 | 付款驗證、花費、聘用率 |
| 💰 報酬合理 | 10 | 對齊底價(時薪底 $20/目標 $25、fixed 底 $200) |
| 📋 需求清晰 | 5 | 寫清楚、有 deliverable |
| 📈 長期潛力 | 5 | 轉長期/回頭客 |

判決：總分 **≥60 = 🟢APPLY**、**≥45 = 🟡MAYBE**、**<45 = 🔴SKIP**。
之後 AI 讀完整 JD 重評，吐 `ai_score`(0-10)+`ai_win`(0-100)，**卡片有 ai_score 就以它為準**。

### 🥊④ 可勝門（搶不搶得到）
- **死亡訊號**：未驗證/0%聘用/提案50+/客戶沒花過錢，命中 ≥2 → SKIP
- **詐騙硬擋**：跳出平台付款、加密貨幣抵薪、股權抵薪、無償試做 → SKIP
- **新帳號硬擋**：Expert × (高競爭/爛客戶/高 Connects) → SKIP
- **勝率上限**：基準 78%(尚無公開星評)，再依未驗證/Expert/高 Connects/缺資料下壓

---

## 5. 怎麼選案（排序）

> **EV = ai_score×10（案子好不好）× ai_win（接不接得到）÷ 100**

兩軸獨立：**好案常常難搶**，所以勝率不計入總分、而是乘進 EV。列表還能切 8 種排序(純分數/勝率/CP值/報酬/競爭最少/客戶花費/能力契合/發布最近)。
加成：**🎯 第一單目標**(小而明確的好案)直接拉 APPLY；**🚫 Connects 紀律**標出別 boost / 別投的案。

## 5.5 🗣️ 語言案通道

**為什麼有這條通道**：2026-07 盤點實際投案史發現，使用者至今全部正面訊號(3 個面試邀請 + 2 個進行中提案)都不是開發案——而是華語錄音、台語配音、台灣腔英文電話錄音、華語 AI 訓練、台灣用戶問卷這類「身分即可交付」的語言/在地案。舊評分規則會把這類案當「非開發職」直接 `SKIP`+`blocked`(`isNonDevRole` 黑名單含 voice over/transcription，或案子沒命中任何開發技能被判 `outOfScope`)——等於把使用者唯一有牽引力的管道全殺光，所以開一條專屬通道。

**判定規則**(`isLanguageCase`，`src/score.js`)：
- **身分詞**必須命中：Mandarin / Taiwanese / Hokkien / Cantonese、chinese speaker/speaking/native/voice/audio/transcri/translat/annotat、native chinese、traditional chinese、zh-TW、taiwan-based / in Taiwan / from Taiwan 等
- **任務詞**也必須命中：record/recording、voice、audio、speak(er)、transcri、translat、interpret、annotat、evaluat、rating、survey、usability、test(er/ing)、role-play、data collection、ai training、proofread、linguist
- **開發職稱排除**：標題若含 developer/programmer/coder/architect/full-stack/back-end/front-end/software engineer → 不算語言案，走原本的開發案流程(例：「Mandarin-speaking React Developer」是開發案，不會被語言案通道誤收)

**評分邏輯**：命中語言案後**完全繞過②能力門**(不吃 `isNonDevRole`、紅線、能力圈外那套)，改成「客戶品質直接定 verdict」：
- 客戶死亡訊號(≥2 個)或雇用率0%+發過3案以上 → `SKIP`(爛客戶還是爛，這條照樣生效)
- 付款未驗證 → `SKIP`
- 付款已驗證 且(客戶花費 ≥ $1000，或 評分 ≥4.5 且 ≥5 則評價) → `APPLY`(規則分定 72)
- 其他(已驗證但客戶普通) → `MAYBE`(規則分定 55)
- 卡片 reason 開頭會標「🗣️ 語言/在地案(華語/台語/台灣身分即可交付，不吃開發能力門)」

**不進 AI 快篩**：語言案(`category='語言案'`)在 `src/run-triage.js` 的兩個 WHERE 條件都會被排除，不會進 `🤖 AI 快篩`。原因：AI 快篩的 prompt 是「開發顧問」人格，會拿開發能力標準亂殺語言案；規則層算出的 verdict 就是最終判斷。

**怎麼用 `searchQueriesLang`**：`config.json` 新增 `searchQueriesLang`(10 條)，跟原本手調的 `searchQueries`(12 條開發案查詢)**分開並存、互不影響**。把這 10 條貼進 Chrome 擴充功能的搜尋設定(跟開發案查詢一起跑即可)，抓進來的語言案會被 `isLanguageCase` 自動辨識、走上面的評分邏輯。

## 5.6 🟢🔴 接案狀態模式

**在哪切換**：sidebar 底部(→ 登出 上方)有「狀態」兩顆小按鈕，點一下即切換，當前模式高亮。

**只有兩個值**：

| | 🟢 空閒(idle，預設) | 🔴 忙碌(busy) |
|---|---|---|
| 價格底線 | 時薪 ≥ $15；fixed $30-150 看範圍(單一明確任務可投，當評價跳板) | 時薪 ≥ $20、fixed ≥ $200，明顯低於此一律略過 |
| AI 快篩/聊天建議 | 小快單通道開，鼓勵買評價 | 對小案直接勸退，底線嚴格執行 |
| Discord 推播門檻 | win ≥ 40 | win ≥ 55，且 fixed < $200 的案不推 |

**影響範圍**：只影響**之後**跑的 AI 快篩提示詞、聊天 agent 建議、Discord 推播門檻——**不會重算**已經存在 DB 裡的分數(`score.js` 規則層完全不受影響，避免切換後舊分數變得不一致)。想讓舊案套用新模式的判斷，要等它們被重新快篩(手動按鈕 / 每日排程 / 新鮮案排程)或用 `npm run refresh` 單案重抓。

## 6. 三條紀律

1. **少投、早投、投準**：EV 榜前幾名 + 第一單目標，一天認真投 1–3 個，別撒網。
2. **絕不亂 boost**：看到「🚫 不要 boost」就別 boost，Connects 留給搶得到的小案。
3. **衝第一個評價**：「🎯 第一單目標」優先投，提議小額付費試做(paid test)降客戶風險。

## 8. 誠實提醒（已知極限）

- **勝率偏樂觀**：多數案 connects/聘用率是空的，最狠的上限觸發不了 → 標「⚠️估」。在乎的案用書籤補真值。
- **規則層會被掛羊頭騙** → 所以 AI 讀完整 JD 是權威。
- **EV 榜是「值得投」榜，不是「保證贏」榜**。0 評價真實中標率約 10–25%，別把 win% 當聖旨。
